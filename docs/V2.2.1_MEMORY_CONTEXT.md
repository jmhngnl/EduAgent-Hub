# V2.2.1 Memory & Context Management

V2.2.1 将“Redis 最近 16 条消息”升级为分层上下文管理：

```text
MySQL Conversation / ChatMessage (durable Source of Truth)
        ↓
Spring Boot Context Snapshot
        ↓
FastAPI ContextManager
        ├── Rolling Conversation Summary
        ├── Recent Message Window
        ├── Token-aware Budget
        └── RAG Evidence Budget
        ↓
LangGraph MessagesState
```

## 核心变化

- MySQL 是 Conversation/ChatMessage 唯一持久化事实源；
- Python 不再维护第二份 Redis Conversation History；
- Redis 继续承担 Refresh Token、Celery Broker/Backend 和运行态职责；
- `conversation` 新增 `context_summary`、`summarized_message_count`、`context_updated_at`；
- 较旧历史增量压缩为 Rolling Summary，最近历史保留原始消息；
- Summary、Recent History、RAG、Current Message 统一进入 Context Budget；
- SSE `done.context_stats` 暴露上下文长度、裁剪与估算 Token。

默认配置：

```env
CONTEXT_MAX_INPUT_TOKENS=16000
CONTEXT_RESERVED_OUTPUT_TOKENS=2500
CONTEXT_SYSTEM_RESERVE_TOKENS=2200
CONTEXT_RECENT_HISTORY_TOKENS=4500
CONTEXT_SUMMARY_MAX_TOKENS=1800
CONTEXT_SUMMARY_SOURCE_TOKENS=7000
CONTEXT_RAG_TOKENS=5000
```

当前 token 计数是 provider-neutral estimate，用于预算而非账单统计。

面试可描述：

> 以 MySQL 作为 Conversation Source of Truth，在 AI Runtime 中实现 ContextManager，
> 通过 Rolling Summary + Recent Window + RAG Evidence 构建分层上下文，并基于
> Token Budget 动态裁剪长对话，降低 Token 成本和无关历史干扰。

本版本仍不是跨 Conversation Long-term User Memory；长期用户事实/偏好提取与检索属于下一阶段。
