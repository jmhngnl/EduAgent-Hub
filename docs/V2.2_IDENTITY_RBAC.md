# EduAgent Hub V2.2 — Identity, Workspace & RBAC

V2.2 moves browser authentication and deterministic authorization into the Java Platform layer.

## Security boundary

```text
React
  │ Bearer JWT + X-Workspace-Id
  ▼
Spring Boot Platform
  ├─ Spring Security
  ├─ User
  ├─ Workspace
  ├─ Membership
  ├─ RBAC
  └─ Redis rotating refresh token
  │ internal service key
  ▼
FastAPI Agent Runtime
  ├─ LangGraph
  ├─ RAG
  └─ Tools
```

The browser never sends the internal Python service key. FastAPI remains an AI runtime and does not become a second JWT authority.

## Roles

| Role | Chat / RAG | Upload / text ingestion | Manage MEMBER / VIEWER | Manage ADMIN |
|---|---:|---:|---:|---:|
| OWNER | yes | yes | yes | yes |
| ADMIN | yes | yes | yes | no |
| MEMBER | yes | yes | no | no |
| VIEWER | yes | no | no | no |

Ownership transfer is intentionally deferred.

## Token model

- Access token: JWT, default 30 minutes.
- Refresh token: opaque random token, SHA-256 key stored in Redis DB 3.
- Refresh is rotating: a refresh token is consumed before a replacement is issued.
- Refresh token is returned only in an HttpOnly, SameSite=Strict cookie.

## V2.1 compatibility

Flyway `V2__identity_workspace_rbac.sql` creates `app_user`, `workspace`, and `workspace_member`, and seeds the existing `demo` workspace.

The first registered/bootstrap user becomes OWNER of `demo`. At that moment, legacy V2.1 conversations where `conversation.user_id IS NULL AND workspace_id='demo'` are claimed by that user.

## Python runtime isolation

Docker Compose binds FastAPI to `127.0.0.1:8000` on the host and uses `PLATFORM_INTERNAL_API_KEY` for Java → Python requests. Within the Docker network the Java Platform uses `http://api:8000`.

## Bootstrap owner

Optional environment variables:

```env
PLATFORM_BOOTSTRAP_USERNAME=owner
PLATFORM_BOOTSTRAP_PASSWORD=replace-with-a-strong-password
PLATFORM_BOOTSTRAP_DISPLAY_NAME=Platform Owner
```

If omitted, the first registered user becomes OWNER of `demo`.
